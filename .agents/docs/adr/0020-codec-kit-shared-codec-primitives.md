# ADR 0020: 提取 codec-kit 共享编解码原语包

- **状态**: Accepted
- **日期**: 2026-08-23
- **关联提交**: `2a37e7d`, `4a5feda`, `faca0ab`, `c9a8131`, `4f30afc`, `23fd807`
- **范围**: `packages/codec-kit`（新增）, `packages/plugins/codec-share`, `packages/plugins/codec-qrcode`

---

## 背景与问题

`codec-share`（分享短链插件）与 `codec-qrcode`（二维码导入导出插件）各自实现了一套底层编解码工具函数（压缩、校验、编码等原语），在代码演进中出现了隐蔽的不一致与行为漂移：

| 编解码能力              | codec-share 实现                         | codec-qrcode 实现                              | 漂移与问题                  |
| :---------------------- | :--------------------------------------- | :--------------------------------------------- | :-------------------------- |
| **周次掩码 (Bitmask)**  | `1 << (week - 1)`，上限 32 周            | `1 << w`，上限 31 周                           | **位偏移差 1 位，互不兼容** |
| **Deflate 压缩**        | `'deflate'` (带 zlib 包装)，手动分块拼接 | `'deflate-raw'`，基于 `Response.arrayBuffer()` | 压缩格式与算法实现不一致    |
| **字符串池 (Interner)** | 上限 255 条，溢出抛出异常                | 无上限约束                                     | 缺少边界校验                |
| **Base64 编码**         | URL-Safe 无填充字符                      | 标准带填充字符                                 | 变体不一致                  |

这种重复实现导致了编解码规则的割裂。我们需要将底层的纯算法原语提取为共享库，同时保持上层传输信封（如版本标识、信封头）由各插件独立维护。

---

## 备选方案否决

| 备选方案                                 | 否决理由                                                                                             |
| :--------------------------------------- | :--------------------------------------------------------------------------------------------------- |
| **迁入宿主 `apps/web`**                  | 违反架构分层；官方编译发布的 ESM 插件无法在运行时反向导入宿主内部私有模块                            |
| **迁入微内核 `@chronos/core`**           | 违反 ADR 0001 微内核边界：内核只容纳平台端口与排课核心模型，通用字节压缩不属于内核职责               |
| **通过 ServiceContainer 提供运行时服务** | 跨插件服务依赖要求提供方必须常驻；而二维码插件为按需异步加载，若服务提供方未加载仍需回退，增加复杂度 |

---

## 架构决策

新建 Workspace 共享包 **`@chronos/codec-kit`**（定位为构建期共享工具库，类似 `@chronos/ui-kit`，而非功能插件），各插件以普通 npm 依赖方式消费。

### 1. 提供的标准接口（纯函数、零业务线格式）

- `deflateRaw` / `inflateRaw`：统一采用 `'deflate-raw'`；浏览器环境使用原生 `CompressionStream`，Node 环境懒加载 `node:zlib`；异常时统一抛错，由调用方决定回退策略；
- `bytesToBase64` / `base64ToBytes` / `bytesToBase64Url` / `base64UrlToBytes`：标准 Base64 及 URL-Safe 变体；
- `crc32` / `appendCrc32` / `verifyAndStripCrc32`：标准 CRC32 校验；
- `writeVarint` / `VarintReader`：可变长整数编解码；
- `MAX_TIMETABLE_WEEK = 32`、`assertValidWeeks`、`weeksToBitmask`（规范为 `1 << (w - 1)`）/ `bitmaskToWeeks`；
- `StringInterner`：字符串池归一化处理。

### 2. 明确不纳入共享包的逻辑

- 各插件专有的线格式信封（如 `"2."`、`"chronos-qr:v2:"`、版本字节标识）；
- Brotli-WASM 动态加载及自适应压缩策略（保留在 `codec-share` 中）；
- 课表对象与字节流之间的具体业务转换逻辑。

### 3. 规范化调整说明

1. 分享链接的 Deflate 算法统一为 Raw 格式，测试环境与浏览器端表现完全一致；
2. 二维码载荷的周次掩码统一对齐为 `1 << (w - 1)` 规范，超出 32 周的非法输入由静默丢弃改为显式报错。

---

## 影响与收益

- **消除底层行为漂移**：全仓周次掩码、CRC32、Varint 及 Base64 算法收敛至单一数据源；
- **构建内联无额外开销**：官方插件打包时由 Rolldown/Vite 自动将 kit 代码内联进 bundle，保持零运行时外部依赖分发；
- **易于扩展新通道**：未来若新增 NFC 或图片识别等课表导出渠道，可直接复用成熟的底层编解码原语。
